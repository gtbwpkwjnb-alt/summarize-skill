# 模块 1：会话精炼 — 发生了什么

## 输出格式

```
📋 {项目名} — {1句话核心概括}

🎯 主任务
  {主任务描述}
  进度 ████████░░ 80%
  > 完成: {已完成部分简述}
  > 待办: {待办部分简述}
  > 阻塞: {如有阻塞项，无则省略此行}

📌 次任务
  {次任务1描述}  ██████░░░░ 60%
  > {简述}
  {次任务2描述}  ████░░░░░░ 40%
  > {简述}
──────────────────────────────
📁 涉及文件({N})
  ✏️ 修改: {file1}, {file2}, ...
  ➕ 新增: {file3}
  🗑️ 删除: {file4}
──────────────────────────────
🔑 关键决策({N})
  - {决策1}：{1句理由}
  - {决策2}：{1句理由}
  > 超{N}条折叠为 📦 等{N}条决策 → $HARVEST_BASE/{project}/{session-id}.md#关键决策
```

## 规则

- **主任务**：当前会话最核心的1个任务（从用户指令推断）
- **次任务**：并行/附带的其他任务，最多列3个
- **进度条**：10格 ASCII 进度条（`█`已完成 `░`未完成），基于已完成步骤/总步骤
- **小字**：`> 小字` 引用块注解细节，不占主行计数
- 无次任务时省略 `📌 次任务` 块
- 无阻塞项时省略 `> 阻塞` 行
- 文件清单超 8 个时，只显示前 8 个 + `…等{N}个文件 📦 → $HARVEST_BASE/{project}/{session-id}.md#文件清单`
- 决策超 5 条时，只显示前 5 条 + `…等{N}条决策 📦 → $HARVEST_BASE/{project}/{session-id}.md#关键决策`

### 决策上下文规则（v7 轮转模式）

每条决策必须附带 `└ 上下文:` 字段。原因：轮转报告进入新会话后，AI 会重新评估所有选择。没有上下文的决策=没有决策。

| 优先级 | 决策类型 | 判断依据 | 显示方式 |
|:------:|---------|---------|---------|
| 🔴 高 | 架构性 | 影响项目结构/技术选型/依赖 | `#{N} {决策} → {结论}` + `└ 上下文: {背景·权衡·被否方案}` |
| 🟡 中 | 配置性 | 工具/环境/配置选择 | `#{N} {决策} → {结论}` + `└ 上下文: {简短理由}` |
| ⚪ 低 | 过程性 | 临时方案/单次操作方式 | 仅计数，不显示详情 |

上下文格式：
```
└ 上下文: {为什么做这个选择}·{否定了什么方案}·{未来可能的变化条件}
```

示例：
```
🔑 #1 Headroom Rust core → 预编译 wheel 提取 _core.pyd
  └ 上下文: 源码编译需拉取全量 crates.io 索引（225+依赖），
    通过 SSH 代理超时。v0.29.0 的 Windows wheel 含 15MB _core.pyd，
    提取即可用。如有编译环境可切回 cargo build
```

### 压缩凭证路径规则

所有折叠标记必须附带可追溯路径，使用 `$HARVEST_BASE` 变量（跨用户兼容）：

```
📦 等{N}个{Noun} → $HARVEST_BASE/{project}/{session-id}.md#{anchor}
```

- `$HARVEST_BASE` = `~/.agents/skills/summarize/harvests/`（技能级固定路径）
- `{project}` = 当前项目名（自动提取）
- `{session-id}` = 当前会话 ID（自动提取）
- `{anchor}` = `#文件清单` / `#关键决策`
