# session-summarize — 建议决策表（v1.2）

本文件是建议生成的唯一规则源。只使用当前可见会话、工具输出、已读取文件和用户确认；不要把重复描述、猜测或旧交接内容当成新证据。

## 输出要求

`## 建议`必须存在，但建议内容可以为空：

- 有成立信号时输出建议，按“解除阻塞 > 限制损失 > 防止复发 > 改善流程”排序。
- 没有成立信号时只写：`暂无基于当前证据的优化或行为建议。`
- 每条采用：`类型：{立即行动|优化建议|行为建议|需确认}。建议：动作及对象。依据：证据；验收：可观测条件。`
- 建议不得重复“下一步”；它必须解释调整理由、防复发措施或行为变化。
- 每条建议必须绑定至少一个可执行对象：失败命令、文件路径、测试命令、配置项或待用户提供的信息；无法绑定时不得提出具体修复。

类型只使用：`立即行动`、`优化建议`、`行为建议`、`需确认`。

## 信号与动作

| 成立信号 | 类型 | 建议动作 | 最小验收证据 |
|---|---|---|---|
| 同一错误特征在两次实际尝试或独立事件中出现，且两次都有工具输出或时间锚点 | 优化建议 | 停止原路径，定位共同前提；改变一个关键变量或补充覆盖该前提的回归测试 | 原失败命令退出码为 0，或指定回归测试通过 |
| 测试、构建或命令失败 | 立即行动 | 保留首个可行动错误，修复后重跑完全相同的验证 | 同一命令退出码为 0，且目标断言通过 |
| 声称完成但没有对应验证 | 行为建议 | 将状态降为“已实现未验证”，执行最小相关验证后再交付 | 报告实际命令、退出码和失败数/通过数 |
| 外部权限、网络或用户输入阻塞 | 需确认 | 列出最小所需输入/授权、默认不执行状态和恢复条件；停止重复请求 | 用户明确提供输入/授权，或确认替代路径 |
| 关键决策缺少理由、被否方案或验收条件 | 行为建议 | 补齐缺失字段；无法恢复理由时标为 `UNKNOWN` | 用户确认决定，或文件/工具证据支持该理由 |
| 用户对同一目标、范围或格式约束进行了至少两次纠正 | 优化建议 | 下次写入前先列目标、边界、验收项并等待确认 | 用户明确确认约束；后续交付不再违反同一项 |
| 恢复的交接报告与当前分支、文件或测试状态不一致 | 立即行动 | 以当前工作区为准，更新 `UNKNOWN`，重新生成交接状态 | `git status`、文件读取或测试结果与新报告一致 |
| 保存内容包含原始对话、疑似凭据或不必要个人信息 | 需确认 | 不保存；删除敏感内容并重新执行校验 | `save_handoff.py --check-only` 退出码为 0 |

## 建议对象约束

- 优先引用当前已读取的具体文件、失败命令、测试入口、配置项或用户待提供的信息。
- 不得只写“加强验证”“持续优化”“定位问题”；必须说明对象、动作和验收。
- 没有可绑定对象时输出：`当前证据不足，先定位，不提出具体修复。`

## 排版与排序

- `## 建议` 必须是报告最后一个区段；不要在建议后追加证据、背景或致谢。
- 按 `解除阻塞 > 限制损失 > 防止复发 > 改善流程` 排序；同类最多输出 2 条，精简模式最多 1 条。
- 建议不重复 `## 下一步` 的动作，而是说明为何需要调整、如何防止复发或需要用户改变什么行为。
- 建议正文采用四行高密度块：`类型`、`建议`、`依据`、`验收`。只有同类建议达到 3 条时才使用表格。

## 判定门槛

- “重复问题”必须同时满足：相同错误特征、两次实际尝试/事件、两份可定位证据。用户或 Agent 重复描述同一事件不算复发。
- 用户确认只能验证意图、约束、决定和授权，不能验证代码、测试或外部事实。
- 代码级建议只有在已读取相关文件时才能引用文件、函数或行号；否则建议先定位，不猜路径。
- 不使用“稳定通过”“加强注意”“持续优化”“关键结果正常”等不可单独验收的表述。
- 标记 `需确认` 后不得执行该动作；列明待决定事项、默认不执行状态和用户答复后的恢复点。
- 历史文件中的单次错误不能直接触发“重复问题”建议；必须同时有当前证据、历史证据和相同失败前提。
