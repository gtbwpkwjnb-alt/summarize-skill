# 深度子命令：`总结 深度 写入`（v8.2 重定义）

> **定位**：将温区高复发错误**以提案形式**呈递给用户，由用户决定是否升级到 L0 P0 表。
> **v8.2 变更**：不再自动写入 L0（与 L0 P0-4「改用户配置前先输出方案」冲突）。改为生成提案 → 用户批准 → AI 执行。

## 触发条件

模块4 判定某条温区错误满足「14d内复发≥2次」时，建议用户运行 `总结 深度 写入`。

## 操作步骤

```
Step 1: Read — 加载当前 L0
  → Read ~/.agents/AGENTS.md → 定位 P0 核心规则段
  → 统计当前 P0 条数（建议 ≤5 条，超出时提示用户）

Step 2: 候选筛选 — 从温区提取
  → Read $HARVEST_BASE/{project}/errors.md
  → 筛选条件: 14d内复发≥2次 且 规则未在 L0 P0 表中
  → 输出候选列表，每条附: 错误简述 + 复发次数 + 建议规则文本

Step 3: 提案输出 — 不直接写入
  → 输出格式:
     "提案: 升级 {N} 条温区规则到 L0 P0 表
      [1] {规则文本}  ← 来源: {错误类型}(复发{N}次)
      [2] ...
      批准方式: 回复 '批准 1' / '批准 1 2' / '全部批准' / '拒绝'"

Step 4: 等待批准 — 用户响应前不动 L0
  → 用户批准 → 进入 Step 5
  → 用户拒绝 → 标记温区条目 [用户拒绝升级 {date}]
  → 用户部分批准 → 只写入批准的条目

Step 5: 执行写入 — 仅在批准后
  → Edit ~/.agents/AGENTS.md P0 表段
  → 失败 → 重新 Read → 重试1次 → 仍失败则报告受阻
  → 成功 → Read 验证 → 进入 Step 6

Step 6: 回测 — 验证写入
  → Read ~/.agents/AGENTS.md → 确认 P0 表已更新
  → 输出: "回测通过: L0 P0 表已含新规则"

Step 7: 询问 commit — 用户决定
	  → 输出: "已写入 L0 P0 表。是否 commit？回复 'commit' 或 'skip'"
	  → 用户回复 commit → git add ~/.agents/AGENTS.md + commit
	  → 用户回复 skip → 跳过，输出警告 "未 commit，建议手动版本控制"
	  → Git 不可用 → 跳过，输出警告

Step 8: 更新温区 — 标记来源
  → 温区对应条目追加 "→ 已升级 L0 P0 表 {date} (用户批准)"
```

## 输出格式

```
深度写入提案:
  ├ Read: ~/.agents/AGENTS.md (P0 表当前 {N} 条)
  ├ 候选: {M} 条温区高复发规则
  ├ [1] {规则文本}  ← 来源: {错误类型}(复发{N}次)
  ├ [2] {规则文本}  ← 来源: {错误类型}(复发{N}次)
  └ 批准方式: 回复 "批准 1" / "批准 1 2" / "全部批准" / "拒绝"
```

批准后输出：

```
深度写入执行:
  ├ 写入: P0-{规则简述} → L0 P0 表
  ├ 回测: ✅ L0 P0 表已更新（{N+1} 条）
  ├ commit: ✅ {sha} "升级温区规则到 L0 [{规则}]"
  └ 温区: 已标记 [升级 {date}]
```

## 错误处理

| 场景 | 行为 |
|------|------|
| L0 文件不可读 | 报告 `受阻：L0 文件不可读`，不写入 |
| Edit old_str 不匹配 | 重新 Read → 重试1次 → 仍失败则报告 `受阻：Edit 失败` |
| Git 不可用 | 跳过 commit，输出警告（写入仍算成功） |
| 温区更新失败 | 不影响 L0 写入成功的结果 |
| 用户拒绝 | 标记温区条目，不再提示该规则升级 |
| 用户未回复 commit | 等待，不自动 commit |

> **v8.2 关键约束**：整个流程**绝不绕过用户批准**。Step 3 输出提案后必须停下来等用户响应。这与 L0 P0-4「改用户配置前先输出方案，等批准再执行」一致。
